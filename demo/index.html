HTS Orchestrator

One spec in, an integrity-checked data package out. The operator decides; the software does the rest.

How it works

From one spec to a data package

1

Spec

One YAML file: compounds, doses, volumes, timing.

2

Validate

Coded checks on DMSO, volumes, tips, reservoirs and time windows.

3

Build

Plate map, iDOT worklist and three Flex protocols, simulator-checked.

4

Execute

Timed steps, logged plate custody, coded fault recovery.

5

Incubate

72 h ± 2 h. State is saved; the process can exit.

6

Package

Data, run record and AnIML, with a SHA-256 manifest that is checked on write.

Plate custody. Every move is written to a hash-chained log. A lost plate stays flagged until an operator confirms where it is.

Instruments

Orchestrator

Sequences steps, keeps the record, decides on faults.

iDOT

Dispenses 30 nL per well from the prep plate (minimum 20 nL).

Opentrons Flex

Dilutions, media, cells and reagent with an 8-channel head.

Robot arm

Plate transfers, each one logged.

Incubator, centrifuge

72 h hold; cell settling.

Plate reader

Luminescence, with a barcode check.

Dose-response design

Every compound well receives the same 30 nL. The gradient comes from five stock concentrations made by 1:4 serial dilution on the prep plate, one source well per point.

Overview

What the orchestrator does

Assay: 384-well ULA round-bottom plate, 20 compounds × 5 concentrations × 3 replicates, 42 negative (solvent) and 42 positive (kill) controls, seeded randomisation. 72 h ± 2 h incubation, CellTiter-Glo 3D readout.

Validation

Coded rules (V-series): DMSO below 0.1%, iDOT volume at or above 20 nL, volumes, tips, reservoirs, edge policy, lysis times, control balance.

Generation

Seeded plate map, iDOT worklist grouped by source well, three Flex protocols using 8-channel multi-dispense.

Execution

Workflow engine over 14 fault codes, a custody state machine, partial-step resume and state persisted across the incubation.

Data package

Per-well readout, deviation flags, Z′ and S/B, hash manifest with checker, AnIML (draft 0.90).

The problem

Why a 72 h spheroid screen is hard to run by hand

Chained timing windows

Doses of 20 to 39 nL (under the 0.1% DMSO limit) need an iDOT. Cells must follow within 60 min; a fully manual compound step takes about 98 min in my model.

A window is broken before seeding.

Dispense-order effects

Cells hold 45 min; reagent lag is predicted at 14.1 of 15 min.

Gradients that look like biology.

One layout, many files

Plate map, worklist and three protocols must agree on every well.

Wrong compound-to-well mapping.

Faults with no one watching

Shortages, a dropped plate, an incubator excursion, a wrong barcode.

Silent deviations in the data.

Timings come from my model and datasheets; they are placeholders until measured.

Recommendation: buy the Flex and iDOT first and add the robot arm later. The arm and its instrument interfaces add about €92,000 of equipment and save about 14 min of carrying per plate.

Timings and costs are model estimates; 42 inputs are placeholders until measured. Compound to cells is the longest wait from the end of iDOT dosing to the cells landing in any well. Reagent lag is the first-to-last-well delay. The Flex is slower than an 8-channel pipette by hand here, but both sit inside the 15 min window. Payback depends on throughput: for Flex and iDOT it is 1.9 years at 4 plates a week, 4.2 years at 2 and 11.5 years at 1.

    Run It Yourself

    Try it live, or run it on your computer

    The live app runs in your browser with your own spec, nothing to install. For the full toolchain, use a terminal: Python 3.13, no lab equipment, runs offline once installed.

    Open the live app Loads in 30 to 90 seconds on the first visit. Runs in your browser; nothing is sent to a server.

    1. Get the project

    Unzip hts-orchestrator and open a terminal in it.

    2. Install it once

    Installs the dependencies.

    python -m venv .venv # macOS / Linux: source .venv/bin/activate # Windows: .venv\Scripts\activate pip install -e ".[dev]"

    Optional: python scripts/fetch_animl_schemas.py downloads the official AnIML schema so the export can be validated.

    3. Check the plan

    Prints every finding; nothing runs yet.

    python -m htsorch validate specs/ctg3d_screen.yaml

    4. Run a full simulated screen

    Builds the files, runs the workflow, writes the package to out/.

    python -m htsorch run specs/ctg3d_screen.yaml --out out --operator "your.name"

    5. Break it on purpose

    Inject a fault: the arm drops the plate.

    python -m htsorch run specs/ctg3d_screen.yaml --out out --scenario scenarios/lost_plate.yaml

    Try scenarios/nobody_there.yaml: the run pauses and prints the resume command.

    6. Run every check

    python -m htsorch scenarios # all 15 failure scenarios python -m htsorch qualify # validation documents against the code python -m htsorch identify # business case from the same plan python -m pytest # the 235 automated tests

    What the exit code means

    0Complete: the data package was written.
    2Waiting or paused for an operator. State is saved; the output prints the resume command.
    3Aborted: no data package.

    Change the experiment

    Edit specs/ctg3d_screen.yaml and re-run validate. See specs/example_*.yaml for typical mistakes.
